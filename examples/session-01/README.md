# Session 01: ビジネスイベントとワークフロー

S1 はコード演習ではありません。予約患者と急患について担当者ごとに書かれた記録からドメインイベントを拾い、コマンドとアクターを添えて、集約と未解決の問いを班で見つけます。進行は、ブリーフィング3分、説明4分、班ワーク6分、レビュー2分の `3+4+6+2=15分` です。

実装は Session 02 から始めます。S1 にコード演習はありませんが、業務イベントを拾う対象のアプリは起動できます。

```bash
pnpm demo:01
```

`http://localhost:3000` で操作し、どの依頼によって何が起きたかを Excalidraw へ書き出します。

## 扱う語彙

- **ドメインイベント**: 業務上起きた出来事。過去形で書きます
- **コマンド**: 誰かが出した依頼。ドメインイベントを引き起こします
- **ワークフロー**: 一つの依頼を受けてドメインイベントを出すまでのひとかたまり
- **集約**: 状態を一貫させたい業務上のまとまり。どのイベントが同じ対象を変更するかを手掛かりに境界を考えます

責任者や更新範囲を決められない箇所には「?」を置きます。ポリシー、読み取りモデル、外部システムは扱いません。型名も S1 では出しません。

## 手順4段

1. 起きた出来事を過去形で書き出す
2. 患者ごとの列に分け、同じ時刻の出来事を並べる
3. それぞれの出来事が、誰の何の依頼で起きたかを添える
4. 一貫性を保ちたい対象ごとにイベントを囲み、集約名と未解決の問いを付ける

## 班ワークの場

班ワークはページ上ではなく Excalidraw で行います。TA がテンプレートを開き、Live collaboration を開始して班へリンクを配ります。

説明4分では、講師が受付スタッフの記録からドメインイベントを1件だけ拾って Excalidraw に置いて見せます。班ワーク6分では、残りのイベントをムギとソラの列へ置き、同じ時刻に別の列で起きたイベントを横に並べます。各イベントに誰の何の依頼で起きたかを添え、一貫性を保ちたい対象ごとに囲んで集約に名前を付けます。2つの列へ影響する判断には「?」を置きます。

レビューでは、ソラの診察開始は獣医師が依頼できる一方、ムギの診察保留を誰が予約へ記録し、受付へ伝えるかは決まっていない点を確認します。保留だけが伝わらない場合に受付と診察室で順番が食い違うことと、見つけた予約集約が S2 以降で扱う対象へつながることがゴールです。
