# Session 00: 引き継ぎ

これは、現在の予約内容と操作ごとの変更履歴を SQLite に残す、意図的に壊れやすい予約管理のスナップショットです。

会計済みの来院を診察中へ戻せること、予約の変更履歴に飼い主の個人情報が残ること、予約だけが変更されて履歴が残らない場合があることを観察します。Session 00 では修正せず、Session 02 から Session 07 で状態、ID、入力と個人情報、失敗、副作用と保存処理を順に改善します。

```bash
pnpm demo:00
```

`http://localhost:3000` で操作と事故を再現できます。SQLite ファイルは `examples/session-00/clinic.sqlite` です。サーバーを停止して起動し直しても、現在の予約内容と変更履歴は残ります。「デモを初期状態へ戻す」を明示的に実行したときだけ、最初の予約内容と変更履歴へ戻ります。

## 事故を再現し、データベースに残った内容を確認する

画面の事故再現パネルで、想定外の状態、ID の取り違え、不正な診察結果、失敗理由の取り違え、操作ごとに変わる時刻と履歴 ID を順に確認します。その後、「現在の予約内容」「予約の変更履歴」「不整合の警告」を見比べます。現在の予約内容と変更履歴が一致するか、変更履歴に不要な個人情報が含まれていないかを確認してください。
