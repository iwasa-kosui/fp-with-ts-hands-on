# Session 00: 引き継ぎ

これは、SQLite に状態保存と監査記録を残す、意図的に壊れやすい予約管理のスナップショットです。

会計済みの来院を診察中へ戻せること、監査記録に飼い主の個人情報が残ること、状態保存だけが先に成功し得ることを観察します。Session 00 では修正せず、Session 02 から Session 07 で状態、ID、入力と個人情報、失敗、副作用と保存境界を順に改善します。

```bash
pnpm demo:00
```

`http://localhost:3000` で操作と事故を再現できます。SQLite ファイルは `examples/session-00/clinic.sqlite` です。サーバーを停止して起動し直しても状態保存と監査記録は残ります。「デモを初期状態へ戻す」を明示的に実行したときだけ、同じ予約済み状態と初期監査記録へ戻ります。

## 事故再現パネルと DB inspection

画面の事故再現パネルで、未知の状態、ID の取り違え、不正な診察結果、失敗理由の取り違え、時刻と監査 ID の直接生成、監査追記だけの失敗を順に実行します。DB inspection では、予約の状態保存を示す JSON、監査記録の JSON、警告を読みます。予約の状態と最新の監査記録が一致するか、監査記録に個人情報が含まれるかを確認してください。
