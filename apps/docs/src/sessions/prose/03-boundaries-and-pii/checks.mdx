<p>直したコードも、次の変更で元に戻ることがあります。たとえば、別の人が <code>parse</code> に <code>raw: any</code> を戻しても、型検査は通ることがあります。ここから先の課題3は、直した状態を保つことです。</p>

<p>悪い変更を機械で検出する仕組みは、Linter の規則、値の性質のテスト、型のテストの3種類です。変更を選んで結果を見比べてください。<code>any</code> や <code>as</code> の書き方は規則とテストが、UUID の検査を外す変更はテストだけが、連絡先を足す変更は型のテストとテストが検出します。</p>

<details class="step-solution">
  <summary>eslint.config.mjs に足す規則の候補</summary>
  <p><code>eslint.config.mjs</code> の <code>rules</code> に <code>"規則名": "error"</code> の形で書きます。</p>
  <ul>
    <li><code>no-explicit-any</code>: <code>any</code> の書き方を検出します。</li>
    <li><code>no-unsafe-assignment</code>、<code>no-unsafe-argument</code>、<code>no-unsafe-member-access</code>、<code>no-unsafe-call</code>、<code>no-unsafe-return</code>: <code>any</code> の値を使う箇所を検出します。</li>
    <li><code>consistent-type-assertions</code> の <code>{`["error", { assertionStyle: "never" }]`}</code>: <code>as</code> の型アサーションを検出します。</li>
  </ul>
  <p>規則名の前には <code>@typescript-eslint/</code> が付きます。</p>
</details>
