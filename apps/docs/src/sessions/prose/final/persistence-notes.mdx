<p>参照実装の store は、受け取ったイベントから予約の現在の状態を取り出し、予約のテーブルの1行に書き込みます。画面とユースケースは、この行から現在の状態を取得します。このように、参照用に現在の状態だけを保持するテーブルを projection と呼びます。監査記録は、テーブル <code>domainEventsTable</code> に別の行として追加します。参照実装は、監査記録を並べ直して現在の状態を再構築することはしません。</p>

<p>1つの transaction にまとめる対象は、1つの業務の操作で同時に成立していなければならない書き込みです。診察開始では、予約の状態と監査記録の2つです。診察結果の記録では、<code>ExaminationCompletionStore</code> が、診察結果の追加、予約の <code>AwaitingPayment</code> への更新、監査記録2件を1つの transaction で保存します。診察結果は保存されたのに予約は診察中のまま、という状態を防ぐためです。</p>

<p>集約の意味は、<a href="/sessions/06-effects-and-consistency/aggregate/">S06 の集約の説明</a>で確認できます。DDD には、1回の保存で更新する集約を1つにするという指針があります。診察結果の記録は、この指針の例外です。これは、予約と診察結果（コード上の名前は ExamResult）の2つの集約を、1つの transaction で保存するためです。参照実装は、両方が同じ SQLite にあり、診察結果だけが保存される状態を避ける必要があるため、この構成を選んでいます。</p>
