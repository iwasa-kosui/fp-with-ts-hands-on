  </article>
  <article class="teaching-topic">
    <h3>ADTは直積型と直和型で型を組み立てる</h3>
    <p>ADT（Algebraic Data Type、代数的データ型）は、型を2つの組み立て方で作る考え方です。1つは「AかつB」を表す直積型で、複数の項目をすべて持ちます。もう1つは「AまたはB」を表す直和型で、複数の候補のどれか1つを持ちます。型が取りうる値の個数を、直積型は掛け算、直和型は足し算で数えられるので、代数的と呼びます。</p>
    <p>予約のように状態を持つデータでは、業務で起こりうる状態だけを型で表したいです。値の個数を数えると、その型が業務で起きない値まで許しているかが分かります。</p>
    <AdtValueCount before={props.teaching[1].before} after={props.teaching[1].after} />
    <p>TypeScriptでは、直積型をオブジェクト型で書き、直和型をUnion型で書きます。直和型の候補がそれぞれオブジェクト型のときは、Session 01 で使ったDiscriminated Unionのように、共通の kind に候補ごとのリテラル値を割り当てて候補を区別します。</p>
    <p class="teaching-topic__why">ADTで状態を表すと、2つの利点があります。1つ目に、取りうる値の組み合わせを型で数えられるので、業務で起きない組み合わせを型から外せます。フラグの直積型は、フラグを足すたびに組み合わせが2倍になりますが、直和型では状態を1個足すと候補が1個増えるだけです。2つ目に、候補を列挙できるので、分岐がすべての候補を処理したかをコンパイラが確かめられます。この確認が、次の節の網羅性検証です。</p>
  </article>
  <article class="teaching-topic">

    <p class="teaching-topic__why">before は未知の文字列を「不明」として受け入れるため、状態を追加しても分岐漏れに気づけません。after でNoShowのcaseを足し忘れると、defaultに残る型はNoShowです。NoShowはassertNeverの引数の型neverに合わないため、コンパイルエラーになります。網羅性検証を使うすべての分岐で、NoShowのcaseを足し忘れた箇所がエラーになるので、コンパイラが新しい状態の影響箇所を示します。assertNeverの戻り値はnever型なので、stringを返す関数のdefaultでそのままreturnできます。</p>
    <h4 id="fail-fast">想定外の値は、見つけた場所で止める（fail-fast）</h4>
    <p>想定していない値を見つけた時点で処理を止める考え方を fail-fast と呼びます。before の default は、想定外の kind にも「不明」という表示名を返して処理を続けます。関数は成功したように見えるので、分岐漏れは、受付画面に「不明」と表示されるまで見つかりにくくなります。after は、分岐漏れを型検査で見つけます。型検査をすり抜けた値が実行時に届いた場合も、assertNever が例外を投げてその場で処理を止めます。</p>
