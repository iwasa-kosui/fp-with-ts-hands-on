  <h3>4つの用語は境界のどこを指すか</h3>
  <p>このセッションで使う4つの用語は、どれも「境界で起きていること」のアニメーションの一部を指します。</p>
  <dl class="boundary-concepts" data-boundary-concepts>
    <dt>Branded Type（内側の型）</dt>
    <dd>値の制約や用途を型の名前で表します。この区別はTypeScriptの型検査で使われ、実行時の値は変えません。詳しくは次の節で説明します。</dd>
    <dt>スマートコンストラクタ（境界の検査）</dt>
    <dd>入力を検査する関数です。検査を通った値だけをその型として返し、制約を満たさない入力は失敗として呼び出し側へ返します。</dd>
    <dt set:html="Parse, don't validate（境界の出口）" />
    <dd>検査の結果を真偽値だけで返し、検査後も元のrawを使い続ける書き方をしません。parseが、成功結果として型付きの値を返します。</dd>
    <dt>Always-Valid Domain Model（内側全体）</dt>
    <dd>ドメインモデルは、予約や診察のような業務の概念と規則を表す型と関数です。境界は、schemaが表す制約を満たさない入力を内側へ入れません。内側の関数は、同じ検査を繰り返しません。</dd>
  </dl>

  <h3>扱う値が変わっても、形は同じ</h3>
  <p>値ごとに変わるのは「外側の姿」「確かめること」「内側の型」だけです。表の1行目の「診察開始の入力」は、先ほどのアニメーションで値が通ったコードに当たります。</p>
  <BoundaryPatterns />
  <h3 id="boundary-result">S03 の Result は、成否だけを持つ小さな型</h3>
  <p>schemaResult が返す <code>Result&lt;T&gt;</code> は、このリポジトリで用意した小さな型です。isOk と isErr で成否を確かめ、_unsafeUnwrap で値を取り出します。失敗の理由は持ちません。Session 04 では、neverthrow というライブラリの <code>Result&lt;T, E&gt;</code> に替わります。E には失敗の理由が入ります。</p>
  <p>_unsafeUnwrap は、Ok なら値を返し、Err なら例外を投げます。名前の unsafe は、Err のときに例外で処理が止まることを表します。S03 の route は、検査に通らなかった入力をその場で止めるために _unsafeUnwrap を使います。Err を例外にせず値として扱う書き方は、Session 04 で学びます。</p>
  <p>AppointmentId.parse は、Zod の schema.parse をそのまま使います。schema.parse は、検査に失敗すると例外を投げます。StartExaminationInput.parse は schemaResult で作るので、失敗を例外ではなく Err として返します。</p>
