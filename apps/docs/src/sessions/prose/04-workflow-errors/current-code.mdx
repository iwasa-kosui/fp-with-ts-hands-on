<p>図は、診察開始で発生しうる3種類の失敗が、route の <code>catch</code> に入る様子を示します。</p>

<CatchConfluence />

<p><strong>課題1</strong>: 1点目は、<code>startExamination</code> の戻り値の型が成功の値だけで、失敗の理由が型に現れないことです。2点目は、route が例外のメッセージの文言で失敗を判別することです。文言を変更すると、型検査は通ったまま判別が外れ、予約なしの失敗も 500 になります。</p>

<p><strong>課題2</strong>: 保存の障害（データベースへの接続が切れるなど）も、同じ <code>catch</code> に入ります。利用者が次の操作を選べる失敗（業務の失敗）と障害を、route が区別できません。</p>

<p><strong>課題3</strong>: 課題1と課題2を直した状態を、今後の変更でも維持することです。誤った変更を検出する仕組みを、演習で追加します。</p>
