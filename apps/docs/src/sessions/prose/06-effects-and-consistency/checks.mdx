<p>課題4は、直した状態を次の変更から守ることです。別の人が <code>new Date()</code> を戻しても、型検査は通ります。ここで扱う変更はどれも型検査を通るので、仕組みは Linter の規則とテストの2つです。手を動かすのは検出の仕組みで、保存する側の実装は読むだけです。</p>

<p>変更を選んで結果を見比べてください。時刻や ID を直接作る変更は規則とテストの両方が、store を2回呼ぶ変更と clock を読み直す変更はテストだけが検出します。</p>

<p>規則は <code>no-restricted-syntax</code> です。<code>selector</code> の <code>[…]</code> には、検出する範囲を絞る条件を書きます。</p>

}, {
  selector: "NewExpression[callee.name='Date'][…]",
  message: "…",
}]`}
