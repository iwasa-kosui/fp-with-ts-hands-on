  <h2>画面操作の結果がデータベースにどう残るか</h2>
  <p>{"\n"}画面で操作すると、現在の予約内容と、各操作を行った後の変更履歴が SQLite に保存されます。{"\n      "}サーバーを起動し直しても両方のデータは残り、{"\n      "}「デモを初期状態へ戻す」を実行したときだけ初期状態へ戻ります。ここでも修正はしません。上の事故報告が、画面のどの操作とどのデータに対応するかを確認します。{"\n"}</p>
  <h3>現在の操作</h3>
  <table>
    <thead><tr><th>担当</th><th>画面で行う操作</th><th>現在の記録</th></tr></thead>
    <tbody>
      <tr><th>受付</th><td>「受付する」を押す。</td><td>予約を来院済みにし、来院時刻を残す。</td></tr>
      <tr><th>獣医師</th><td>「診察を開始する」を押し、診察を終えたら「診察結果を記録する」を押す。</td><td>診察を開始するとき、担当の獣医師と開始時刻を残す。診察結果を記録するとき、診断、処置、診察項目と終了時刻を残し、予約を会計待ちにする。</td></tr>
      <tr><th>会計担当</th><td>「会計を記録する」を押す。</td><td>予約を会計済みにし、請求額と会計をした時刻を残す。</td></tr>

  <h3 id="code-layout">配布コードの構成</h3>
  <p>配布コード <code>examples/session-00/src</code> は、役割ごとにディレクトリを分けています。矢印は import の向きです。</p>
  <CodeLayoutDiagram />
  <p>リポジトリは、データベースの読み書きをまとめたオブジェクトです。診察開始では、<code>repository.find</code> で予約を読み、<code>repository.save</code> で現在の予約内容を上書きし、<code>repository.appendAudit</code> で変更履歴を追加します。</p>
  <p>Web サーバーには <code>Hono</code> を使います。データベースは SQLite で、<code>better-sqlite3</code> で接続し、<code>Drizzle ORM</code> で SQL を組み立てます。</p>
