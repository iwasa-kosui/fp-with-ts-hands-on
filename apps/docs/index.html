ところが、問題が増えてきた

便利になった分だけ、要求も増えました。小さな改修を重ねるうちに、どの状態で何ができるのか、どの情報を外へ出してよいのかが分かりにくくなっています。

Problem 00 🐢 会計済みが診察中へ戻る 再診対応の改修後、閉じたはずの来院が診察室へ戻れるようになった。
Problem 01 🐕 キャンセル理由が残らない 理由や再診希望日が、必要な状態にだけ結びついていない。
Problem 02 🐾 ID を取り違える 外部検査 payload の petId と ownerId を間違えても気づきにくい。
Problem 03 🎫 連絡先がログに出る 調査のためのログが、飼い主の個人情報まで含んでしまう。
Problem 04 🧪 失敗理由が UI に出せない throw と undefined が混ざり、スタッフに理由を説明しづらい。
Problem 05 📜 変更を後から追えない いつ誰が診察開始したのか、事故調査でたどりにくい。
Help wanted 🐈 急募！どうにかしてくれるエンジニア 便利な WAN NYAN OS を、変更に強いシステムへ立て直したい。
