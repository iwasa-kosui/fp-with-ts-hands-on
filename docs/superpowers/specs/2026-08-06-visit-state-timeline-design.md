# 来院状態タイムライン設計書

## 目的

Module 00 の「来院をモデリングしよう」で、状態名の対応表を読むのではなく、来院で起きる業務を上から順に追うことで、読者が「出来事によって状態が変わる」と捉えられるようにする。

## 解決する問題

4列の表は、スマートフォンでは各列が極端に狭くなり、業務イベント・遷移前後・状態に残る情報を視線で往復しなければならない。特に英字の状態値が折り返され、主経路とキャンセル分岐を一続きの業務として読み取れない。

## 採用する表示

縦方向の「業務イベントのタイムライン」を採用する。各ステップは、読者が次の順で読める1つのまとまりにする。

1. 業務イベントを見出しとして表示する。
2. 実行者を補助情報として表示する。
3. 遷移前と遷移後を矢印でつなぎ、日本語の状態名を状態チップとして表示する。
4. 状態に残す情報を一文で表示する。

通常の主経路は `予約を受け付ける`、`来院を確認する`、`診察を開始する`、`会計を確定する` の4ステップとする。各ステップは、現在の教材とドメインモデルに対応する以下の遷移を示す。

- 来院記録なし → 予約済み（`scheduled`）
- 予約済み（`scheduled`）→ 受付済み（`checked-in`）
- 受付済み（`checked-in`）→ 診察中（`in-examination`）
- 診察中（`in-examination`）→ 会計済み・来院完了（`paid`）

英字の状態値は、日本語の状態名に従属するコード表示にする。状態名が先に読め、値は実装との対応を確認したい読者だけが見る順序にする。

## 分岐と終端状態

キャンセルは主経路の途中へ混在させず、タイムライン直後の分岐カードとして表示する。起点となる担当者は「飼い主または病院」と明記し、`予約済み` または `受付済み` からだけ `キャンセル`（`canceled`）へ遷移する。キャンセル理由、キャンセル時刻、任意の再診希望日を残すことを示す。

最終ステップの直後には、`Paid` と `Canceled` が終端状態であることを強調する。会計済みの来院を診察中へ戻す業務は存在せず、再診は新しい予約として扱う。通常の再診手順は今回の演習範囲外とする。

## 実装境界

- 変更対象は `apps/docs/src/pages/modules/00-break-the-app.astro` の `#visit-modeling` 節と、タイムライン用スタイルを置く `apps/docs/src/styles/modules.css`、表示契約を確認する `apps/docs/src/test/pages/modules/module-00.test.ts` に限る。
- ドメインモデル、演習、他のモジュールの説明は変更しない。
- SVG、JavaScript、画像を追加しない。順序付きリスト、見出し、段落、`aside` で意味構造を保ち、CSS は小画面で1列に読めることだけを支える。
- 既存の `#visit-state-transitions` ID は、回帰テストとページ内の安定した参照先として順序付きリストへ引き継ぐ。

## 検証

静的レンダリングテストで、表ではなく順序付きリストであること、4つの主経路、各ステップの実行者・状態遷移・保持情報、キャンセル分岐、終端状態と再診の範囲を確認する。実装後にドキュメントテスト全体と Astro の型検査・静的ビルドを実行する。
