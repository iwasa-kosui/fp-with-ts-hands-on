# Module 00 Customer-Journey Onboarding Design

## 背景

Module 00 は開発メンバー向けのオンボーディングとして、プロダクト、来院の状態、教材コードを紹介する。しかし、状態値や実装の説明が業務上の体験より先に来るため、初見の参加者には「誰のどんな困りごとを守るのか」が伝わりにくい。

## 目標

Module 00 を直接開いた参加者が、最初の事故に取り組む前に次を説明できるようにする。

1. 飼い主と病院スタッフの言葉で、1回の来院がどのように完了するか。
2. 各機能が誰にどんな価値を届けるか。
3. 来院の業務上の流れが、アプリの状態値でどう表現されるか。
4. 自分が開発者として、どのコードを読み、何を確かめるか。

## 対象外

- 実運用における再診の正規フローを新たに仕様化しない。
- PRD全文や後続モジュールの詳細をModule 00へ複製しない。
- 既存のSPAルート、Module 00の事故シナリオ、共通の演習フローを変更しない。

## 情報設計

Module 00 のヒーロー直後に、以下の順でオンボーディングを表示する。

### 1. この開発に参加するあなたへ

主対象であるTypeScript開発者に向けて、完成形を一度に作るのではなく、業務事故から守るべきルールを見つけ、小さな改善と確認を繰り返すワークショップであることを説明する。

### 2. 1回の来院で起きること

実装用語を使わず、飼い主と病院スタッフの体験として次を説明する。

1. 飼い主が診察を予約する。
2. 来院後、スタッフが受付を済ませる。
3. 獣医師が診察し、カルテに記録する。
4. 会計を済ませると、その来院は完了する。
5. 再診が必要なら、会計済みの来院を開き直さず、新しい来院として扱う。

この段階では `scheduled` などの状態値を出さない。

### 3. 機能が届ける価値

次の3列を持つ意味論的な表で、機能・相手・価値を対応付ける。

| 機能 | 届ける相手 | 価値 |
| --- | --- | --- |
| 予約・受付 | 受付スタッフ、飼い主 | 来院を迷わず正しく受け入れられる。 |
| 診察・カルテ | 獣医師、病院スタッフ | 診療の記録を一貫して扱える。 |
| 会計 | 会計担当、飼い主 | 確定した来院記録と会計を誤って壊さない。 |
| フォロー・連絡先・申し送り | 病院スタッフ、飼い主 | 必要な連絡を安全に引き継げる。 |

### 4. アプリは業務をどう表すか

顧客・現場の流れを理解した後で、業務段階と状態値を対応付ける。

| 業務上の段階 | アプリ上の状態 |
| --- | --- |
| 予約済み | `scheduled` |
| 受付済み | `checked-in` |
| 診察中 | `in-examination` |
| 会計済み・来院完了 | `paid` |

`paid` は会計済みの来院が完了したことを示す。今回の演習では、その来院を診察中へ戻すことを禁止する。再診の正規操作は対象外とする。

### 5. 開発者として今日行うこと

既存のコード地図を保ち、`src/legacy`、`exercises`、`test`、`src/clinic` の役割と、事故から不変条件を読む最初のタスクを説明する。後続モジュールは技法名の列挙ではなく、守る価値との関係で短く予告する。

## コンテンツモデル

既存の `overview` ブロックは、「開発に参加するあなたへ」「1回の来院で起きること」「アプリは業務をどう表すか」「開発者として今日行うこと」に使う。

機能・相手・価値には、次の専用ブロックを追加する。

```ts
type ContentBlock =
  | /* existing variants */
  | Readonly<{
      kind: "value-map";
      heading: string;
      introduction: string;
      rows: readonly Readonly<{
        function: string;
        audiences: string;
        value: string;
      }>[];
    }>;
```

レンダラーは `<section>` 内に `<h2>`、`<p>`、`<table>`、`<thead>`、`<tbody>` を生成し、列見出しには `scope="col"` を設定する。全テキストは `textContent` で設定し、`innerHTML` は使わない。

## テスト

- Module 00のコンテンツテストで、顧客・現場の言葉による来院の5段階、4つの価値マップ行、状態対応表、開発者の到達価値を検証する。
- ブロックレンダラーテストで、`value-map` が見出し・説明・列見出し・全行を意味論的な表として描画することを検証する。
- ページテストで、表示順が「あなたの役割 → 来院の体験 → 機能と価値 → 状態対応 → 最初の事故」であり、各セクションが既存の目次に含まれることを検証する。
- 既存の正規ルートと、Module 01以降で `introBlocks` を持たない場合の表示順を維持する。
