# Module 00 オンボーディングの階層構造

## 背景

Module 00 の導入は、参加者への案内、来院の流れ、機能と価値、来院の扱い、今日の作業という性質の異なる情報を、同じ見出し・同じカードとして並べている。初見の参加者は読む順序をつかみにくく、読み返す参加者は目次から必要な情報へ移動しにくい。

導入を 1 つの章として扱い、上から読める流れと、見出しから戻れる参照性を両立する。

## 目的

- 開発に参加したメンバーが、動物病院の業務から今日の演習までを順に理解できるようにする。
- 来院の流れ、登場人物、機能と価値、コード上の表現を、情報の性質に合った形で示す。
- 後から読むときは、目次から各区画へ直接移動できるようにする。
- Module 01 以降の表示と既存のコンテンツブロックの見出し構造を変えない。

## 対象外

- 動物病院の業務手順を新たに決めること。
- Module 01 以降の画面構成を変更すること。
- 導入を折りたたみ式の説明へ変更すること。

## 情報の構成

Module 00 の先頭に、`開発に参加する前に` という 1 つの章を置く。章は H2、内部の区画は H3、`登場人物` は来院の流れに属する H4 とする。

```text
開発に参加する前に
├─ 動物病院の役割
├─ 1回の来院の流れ
│  └─ 登場人物
├─ 提供する機能と価値
├─ 来院をモデリングしよう
└─ 開発者として今日取り組むこと

システム障害
```

`システム障害` 以降の既存の実習は、この章の後に従来どおり配置する。導入の 5 区画を実習と同格の H2 や独立したカードにはしない。

## 各区画の内容と表示

### 動物病院の役割

飼い主が安心して来院でき、病院スタッフが予約から会計までを一貫して扱えるようにするアプリであることを伝える。ここで業務の背景を説明し、技術的な用語から始めない。

### 1回の来院の流れ

予約、受付、診察と記録、会計と完了を順番のあるリストとして表示する。順序が意味を持つため、箇条書きではなく `ol` を用いる。再診の通常の手順は今回の演習対象外であることだけを示し、手順を新たに定義しない。

#### 登場人物

飼い主、受付スタッフ、獣医師、会計担当を、それぞれが来院のどの場面に関わるかとともに表示する。人物と説明の対応が分かる意味論的なリストを用いる。

### 提供する機能と価値

予約・受付、診察・カルテ、会計、フォロー連絡・連絡先の管理・申し送りを、利用者と得られる価値に対応付ける。既存の表を再利用し、列は `機能`、`利用者`、`価値` とする。

### 来院をモデリングしよう

利用者に見える来院の進み具合と、コードで扱う値を対応付ける。予約済み、受付済み、診察中、会計済み・来院完了の順を示し、会計済みの来院を診察中へ戻さないことを今回守るルールとして説明する。

### 開発者として今日取り組むこと

参加者が読む場所（`src/legacy`、`exercises`、`test`、`src/clinic`）と、システム障害を再現してから小さな改善と確認を行う流れを示す。後続モジュールの技法名を先に並べず、今日の演習への導線を優先する。

## 表示と目次

- 導入全体を 1 つの `section` として描画し、外側だけに既存のカード装飾を適用する。
- 内部の区画はカードにせず、見出し、余白、区切り線で区切る。各区画の表、順番のあるリスト、人物のリストは意味に合う HTML 要素で描画する。
- 章と各区画の見出しには、一意のフラグメント識別子を付ける。
- 目次では H2 を親項目、H3 と H4 を子項目として入れ子にする。初見では上から読め、読み返しでは子項目を選んで移動できる。
- 他モジュールは、現在どおり各実習の H2 を平坦な目次に表示する。

## データ構造とレンダリング

Module 00 専用のオンボーディング章を、親見出しと順序付きの区画として表す。既存の `introBlocks` を単に並べ直すのではなく、親子関係と表示形式をデータ構造に含める。

区画は少なくとも次の区別を持つ。

- 業務の背景を説明する文章
- 来院の手順と登場人物
- 機能・利用者・価値の表
- 来院の進み具合とコード上の値の対応
- 開発者が今日取り組むこと

レンダラーは、通常の実習ブロックの H2 表示を維持する。オンボーディング章だけは、親が H2、子が H3、登場人物が H4 となるように描画する。

## 検証

- Module 00 の先頭が `開発に参加する前に` の H2 であり、承認済みの H3/H4 順序を持つこと。
- 来院の流れが順番のあるリスト、登場人物が役割の説明を持つリスト、機能と価値が列見出しを持つ表として描画されること。
- 目次が章と子区画の親子関係、各フラグメントへのリンクを持つこと。
- 導入の子区画が独立したカードにならないこと。
- Module 01 以降の見出し、目次、表示順が変わらないこと。
- docs のテスト、型検査、ビルドが成功すること。
