# Astro静的コンテンツ移行設計

## 背景

`apps/docs` は現在、Viteで起動するクライアントサイドSPAとして実装されている。モジュール本文は `ModuleContent` と `ContentBlock` による大きなTypeScriptオブジェクトへ格納され、汎用レンダラーがDOM APIでページを組み立てる。

この構成では、モジュール固有の表現を追加するたびに、コンテンツ型、汎用レンダラー、スタイル、複数の構造テストを同時に拡張する必要がある。PR #17のModule 00オンボーディング改善でも、内容の階層化が型とレンダラーの拡張へ波及している。

コンテンツの構造化は、検索、再利用、機械処理などの必要性が具体化した時点では有用である。ただし現段階では、各モジュールを教材として改善する自由度を優先し、本文を先回りして共通スキーマへ閉じ込めない。

## 目的

- `apps/docs` をAstroによる静的サイトへ移行する。
- 各モジュール本文を、ページ固有の `.astro` ファイルへ通常のHTMLとして直接記述できるようにする。
- Reactは、ブラウザ上の操作が必要な小さなアイランドだけに使用する。
- PR #17で改善されたModule 00の内容を失わず移行する。
- トップページの既存の見た目を厳密に維持する。
- 既存URL、Cloudflare Workersでの配信、プレビュー運用を維持する。
- PRDの学習要件と、全モジュールの既存教材内容を維持する。

## 対象外

- リポジトリ直下の `docs/` にあるPRD、設計書、計画書、イベント資料のAstro移行
- Astro Content Collections、MDX、外部CMSによる本文の構造化
- モジュール本文をReactアプリケーションとして実装すること
- Cloudflare WorkersでのSSR
- 演習コードやドメインモデルの変更
- トップページのデザイン変更

## 移行元

実装ブランチは、PR #17 `plan-module-00-app-overview` の先端 `f3d1b02` を起点とする。これにより、Module 00の顧客体験、登場人物、機能と価値、来院モデリング、目次階層の改善を移行対象へ含める。

## 採用する構成

Astroのファイルルーティングを使い、モジュールごとに独立した静的ページを持つ。

```text
apps/docs/src/
├── components/
│   ├── CodeBlock.astro
│   ├── CommandBlock.astro
│   └── CopyButton.tsx
├── layouts/
│   ├── BaseLayout.astro
│   └── ModuleLayout.astro
├── modules/
│   └── catalog.ts
├── pages/
    ├── 404.astro
    ├── index.astro
    └── modules/
        ├── 00-break-the-app.astro
        ├── 00-read-the-incident.astro
        ├── 01-state-modeling.astro
        ├── 02-boundary-and-ids.astro
        ├── 03-result-errors.astro
        ├── 04-agent-review.astro
        └── 05-mini-integration.astro
└── styles/
    ├── base.css
    └── modules.css
```

### `BaseLayout.astro`

HTML文書、メタデータ、共通スタイルの読み込みを担当する。ページ本文のセクション構成は決めない。

### `ModuleLayout.astro`

モジュール共通のヘッダー、ケースファイル形式のヒーロー、ページ内目次領域、前後ナビゲーションを担当する。本文は既定の `slot` として受け取り、本文中の見出し、表、図解、セクション順を制限しない。

### `modules/catalog.ts`

一覧、前後ナビゲーション、ページの基礎表示に必要な次の情報だけを持つ。

- slug
- モジュール番号
- タイトル
- 所要時間
- 対象の動物とアイコン
- ページの短い要約

本文、演習手順、コード例、セクション定義は持たない。将来コンテンツを構造化する場合も、このカタログと本文を別々に移行できる境界を保つ。

### モジュールページ

各 `.astro` ファイルが教材本文を直接持つ。ページ固有のレイアウト、図解、表、定義リスト、コード、注釈を通常のAstroテンプレートとして追加できる。本文をページローカルのJSON風オブジェクトへ移し替えることはしない。

### Reactアイランド

Reactは `CopyButton.tsx` のようにユーザー操作とクライアント状態を必要とする部品だけへ限定する。本文、目次、前後ナビゲーション、コード本体はAstroで生成し、不要なクライアントJavaScriptを配信しない。

最初の移行では、コマンドをクリップボードへコピーするボタンを `CommandBlock.astro` 内からReactアイランドとして利用する。

## コンテンツ移行

既存の `ModuleContent` フィールドと `blocks` を機械的に同じ順番で描画しない。各モジュールを一つの読み物として再構成し、重複を除きながら固有の情報を移す。

次の情報は維持する。

- 学習目的
- 要求、事故、レビュー要求
- 守るべき不変条件
- RedとGreenの演習コマンドおよび期待結果
- 読むファイルと編集対象
- 採用する技法、その理由、適用限界
- コード例と参考リンク
- レビュー観点と完了条件
- 業務への転用と振り返り設問
- 実装できない場合の代替進行
- 最終演習の行動計画
- PR #17で追加されたModule 00のオンボーディング内容

重複する説明は一つへ統合できる。汎用レンダラーの都合で付けられた見出しや順序は、学習の流れに合わせて変更できる。

## ビジュアル設計

### トップページ

既存のHTML構造、クラス名、文章、CSS、レスポンシブ挙動を維持して `index.astro` へ移植する。トップページにはReactを使わない。Astro化に必要な文書シェル以外の再設計を行わない。

### モジュールページ

「ケースファイル」を基本テーマとする。参加者が動物病院の事故または要求を調査する教材として、物語と演習手順の両方を追いやすくする。

- 冒頭にモジュール番号、所要時間、対象の動物、事故または要求を表示する。
- 本文は長文を読みやすい一列のリーディングカラムとする。
- デスクトップではページ内目次を左側へ配置する。
- スマートフォンではページ内目次を折りたたんで本文を優先する。
- Red、Green、守る不変条件、編集対象を色とラベルで区別する。
- トップページとつながるミント、レモン、コーラルを基本色にする。
- モジュールごとにアクセント色、図解、セクション構成を変えられる。
- カードの多用を避け、意味的な見出し階層と文章の流れを優先する。

## ルーティング

クライアント側の `app.ts` と `routes.ts` を廃止し、Astroのファイルルーティングへ移す。

- `/`
- `/modules/00-break-the-app/`
- `/modules/00-read-the-incident/`
- `/modules/01-state-modeling/`
- `/modules/02-boundary-and-ids/`
- `/modules/03-result-errors/`
- `/modules/04-agent-review/`
- `/modules/05-mini-integration/`
- `/404.html`

Astroの `trailingSlash` は `always` とし、既存の末尾スラッシュ付きURLを正規URLとして維持する。

`/module-00/` は互換URLとして残し、静的ページは生成せず、Workerから `/modules/00-break-the-app/` へ308リダイレクトする。

## Cloudflare Workers配信

Astroは既定の静的生成を使用する。Cloudflare adapterは追加せず、生成物を現在と同じ `apps/docs/dist` から配信する。

`wrangler.jsonc` は次の方針へ変更する。

- `assets.directory` と `ASSETS` bindingを維持する。
- `not_found_handling` を `single-page-application` から `404-page` へ変更する。
- `/healthz` と `/module-00/` はWorkerを先に実行する対象にする。

`worker/index.ts` は `/healthz` の応答を維持し、`/module-00` と `/module-00/` に308リダイレクトを追加する。それ以外は静的Assetsへ委譲する。

## エラー処理

- 存在しないページはSPAのトップページへフォールバックさせず、生成済みの404ページを404ステータスで返す。
- コピー操作に失敗した場合、Reactアイランドは成功表示に切り替えず、再試行できる状態を保つ。
- JavaScriptが無効な環境でも、本文、コマンド、目次、前後ナビゲーションは利用できる。
- モジュールカタログに存在しないslugは、ビルド時またはテスト時に検出する。

## テスト方針

コンテンツオブジェクトの内部構造ではなく、生成されたページとユーザーが利用する振る舞いを検証する。

### カタログ

- slugとモジュール番号が重複しない。
- モジュールの順序が既存の学習順と一致する。
- すべてのカタログ項目に対応する静的ページがある。
- 前後ナビゲーションが先頭、中間、末尾で正しい。

### 静的ページ

- 全モジュールURLがHTMLとして生成される。
- 各ページに固有のタイトル、主要な学習内容、演習コマンドが存在する。
- 内部リンクが生成済みページまたは明示した互換URLを指す。
- 404ページが生成される。
- モジュールページが意味的な見出し階層とナビゲーションを持つ。

### Reactアイランド

- コピー操作の成功時に表示が更新される。
- Clipboard APIの失敗時に成功表示へ変化しない。
- コピー対象のコマンド文字列が改変されない。

### トップページ回帰

- 主要なHTML構造、クラス、ナビゲーション、文章が維持される。
- 既存CSSを移植し、トップページ用セレクタを失わない。
- 移行前後のスクリーンショットをデスクトップ幅とスマートフォン幅で比較する。

### 完了時のコマンド

- `pnpm --filter @fp-with-ts/docs test`
- `pnpm --filter @fp-with-ts/docs typecheck`
- `pnpm --filter @fp-with-ts/docs build`
- `pnpm test`
- `pnpm typecheck`
- `pnpm build`

## 削除する構成

Astro版への移行後、次のVite SPA固有またはコンテンツスキーマ固有の構成を削除する。

- `apps/docs/index.html`
- `apps/docs/vite.config.ts`
- `apps/docs/src/main.ts`
- `apps/docs/src/app.ts`
- `apps/docs/src/routes.ts`
- DOM APIで構築している `pages/` と `components/`
- `apps/docs/src/content/module-content.ts`
- `apps/docs/src/content/modules/` の本文オブジェクト
- 上記内部構造だけを検査するテスト

削除前に、各ファイルが持つ固有の文章と振る舞いがAstroページまたは新しいテストへ移ったことを確認する。

## 実装順序

1. Astro、React、テスト環境と静的配信設定を用意する。
2. トップページを見た目を維持したままAstroへ移す。
3. 共通レイアウト、モジュールカタログ、ケースファイルのビジュアル基盤を作る。
4. PR #17版Module 00をAstroへ移す。
5. 残りのモジュールを一ページずつ移し、ページ単位で検証する。
6. 404、互換リダイレクト、Reactコピー操作を実装する。
7. 旧SPA、旧コンテンツ型、旧レンダラー、内部構造テストを削除する。
8. 全体テスト、型検査、ビルド、スクリーンショット比較を実施する。

## 完了条件

- PR #17の内容を含む全モジュールがAstroの静的ページとして閲覧できる。
- モジュール本文がJSON風オブジェクトや共通ContentBlock unionへ格納されていない。
- 各モジュールが固有のAstroマークアップとレイアウトを自由に持てる。
- Reactが操作を必要とする小さなアイランドだけに限定されている。
- トップページの見た目が移行前と一致する。
- 既存URLと互換リダイレクトが機能する。
- 存在しないURLが404になる。
- Cloudflare Workersのヘルスチェックと静的Assets配信が機能する。
- ドキュメントサイトと演習コードを含む全体のテスト、型検査、ビルドが成功する。
