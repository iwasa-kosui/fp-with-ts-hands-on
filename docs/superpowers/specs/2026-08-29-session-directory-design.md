# セッション一覧と開始導線 設計

- 日付: 2026-08-29
- 状態: 設計承認済み・実装計画待ち

## 背景

トップページのヘッダーは `SESSION 00` から最初のセッションへ直接遷移します。この導線ではカリキュラム全体を確認してから開始できず、途中のセッションや Final Session を選ぶ入口もありません。また、現在のサイトには `/sessions/` の一覧ページがありません。

ヘッダーの導線を `START SESSION` に変更し、Session 00〜06 と Final Session を順番に確認できる一覧ページを新設します。

## 目標

- トップページからセッション一覧へ移動できる `START SESSION` CTAを提供する。
- CTAをデスクトップとモバイルの両方で表示する。
- `/sessions/` に8件のセッションをカリキュラム順で表示する。
- 一覧に番号、所要時間、タイトル、概要を表示し、各セッションへ移動できるようにする。
- 各セッションページが自身のメタデータを所有する現在の設計を維持する。

## 対象外

- 各セッションの本文、順序、所要時間、前後ナビゲーションの変更。
- 進捗保存、完了状態、認証、参加者ごとの表示切り替え。
- トップページ下部にある Session 00 の説明や既存導線の変更。
- セッション共通カタログの再導入。

## トップページの導線

ヘッダー内の `SESSION 00` リンクを `START SESSION` に変更し、遷移先を `/sessions/` とします。画面遷移を行うため、HTML要素は `<button>` ではなくリンクを使い、主要CTAと分かるボタン風の見た目にします。

デスクトップでは既存のページ内ナビゲーションと並べます。モバイルではページ内ナビゲーションを引き続き非表示にし、`START SESSION` だけを表示します。これにより、画面幅によって主要導線が失われないようにします。

## セッション一覧ページ

`/sessions/` は既存セッションページと同じ配色とサイトヘッダーを使います。ページ冒頭で一覧であることと、Session 00から順番に進めることを示します。

一覧には次の情報を持つカードを8件表示します。

- セッション番号
- 動物のアイコン
- 所要時間
- タイトル
- 概要
- 各セッションページへのリンク

表示順は Session 00〜06、Final Session とします。デスクトップは2列、モバイルは1列にし、読み順とDOM順を一致させます。

## メタデータの取得

一覧ページは各 `apps/docs/src/pages/sessions/*.astro` が公開している `session` をビルド時に読み込みます。`index.astro` 自身は対象から除外し、`sequence` に基づいて Session 00〜06、Final Session の順へ並べます。

タイトルや概要を一覧ページへ複製せず、既存のページ所有構造を維持します。共通カタログは作成しません。

## 静的ビルドとの整合

静的ビルド検証では、`sessions/index.astro` をセッション本文ページとして数えず、`sessions/index.html` を一覧ページとして明示的に検証します。内部リンクの許可対象に `/sessions/` を加えます。

セッション本文ページだけを読み込む既存テストも `index.astro` を除外し、8件のカリキュラム契約を維持します。

## アクセシビリティ

- CTAとカードはリンクとして実装し、キーボード操作と通常のリンク挙動を維持します。
- `START SESSION` は背景色だけに頼らず、境界線、文字色、フォーカス表示でCTAだと分かるようにします。
- 一覧は見出し階層とリスト構造を使い、順序と項目数を支援技術から把握できるようにします。
- 動物のアイコンは装飾として扱い、カードの名前はテキストから取得できるようにします。

## テスト方針

### TDD

最初にブラウザテストを追加し、トップページに `/sessions/` を指す `START SESSION` がないことと、一覧ページが存在しないことによる失敗を確認します。その後、最小のページとスタイルを実装してテストを通します。

### 自動テスト

- トップページのCTAの文言、遷移先、実際の画面遷移を確認する。
- 一覧に8件がカリキュラム順で表示され、各リンク先が対応するセッションであることを確認する。
- セッションメタデータのページ所有契約が維持されることを確認する。
- 静的ビルドで `/sessions/` と全内部リンクが解決できることを確認する。
- docs全体のテストとビルドを実行する。

### 視覚検証

トップページと一覧ページをモバイル幅、デスクトップ幅の順で確認します。トップページの既存スナップショットは、CTAの意図した差分だけを更新します。一覧ページにも両方の幅のスナップショットを追加し、カード順、折り返し、はみ出し、フォーカス可能な導線を確認します。

## 受け入れ条件

- トップページに `SESSION 00` ではなく `START SESSION` が表示される。
- `START SESSION` から `/sessions/` へ移動できる。
- CTAがモバイルとデスクトップの両方で表示される。
- `/sessions/` に Session 00〜06 と Final Session の8件が順番どおり表示される。
- 各カードから対応するセッションページへ移動できる。
- セッション情報の正本は各セッションページにあり、一覧ページへ重複して定義されない。
- docsのテスト、静的ビルド、モバイルとデスクトップの視覚検証が成功する。

## 採用しなかった方式

### 一覧ページに8件の情報を直接記述する

実装量は少ないものの、セッション名や所要時間を変えるたびに本文ページと一覧ページの両方を更新する必要があります。表示内容の不一致を防ぐため採用しません。

### 共通カタログを再導入する

一元管理はできますが、現在は各ページがメタデータと表示を所有する構成をテストで保護しています。今回の一覧追加だけを理由に所有境界を変更すると影響範囲が広がるため採用しません。
