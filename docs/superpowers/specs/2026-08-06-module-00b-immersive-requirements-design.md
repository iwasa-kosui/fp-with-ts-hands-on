# MODULE 00-B 要求導入の没入感向上

## 目的

MODULE 00-B「事故報告を読む」の導入を、抽象的な説明から始めるのではなく、飼い主と受付スタッフが交わす具体的な要望から始める。参加者が業務上の困りごとを理解したうえで、状態とデータを整理する演習へ入れるようにする。

## 導入の流れ

`#requirement` の見出しを「要求を整理しよう」に変更し、次の順序で表示する。

1. 飼い主の吹き出しで、予約のキャンセルと再診希望を伝える。
2. 受付スタッフの吹き出しで、キャンセル理由と再診希望日を記録して次回対応へつなげたい、と伝える。
3. 強調した参加者向けの文で「この要望を安全に扱うには、まず要求を整理しよう。どの状態に、どの情報が必要でしょうか」と問いかける。
4. 既存の `Canceled` 状態に必要なデータと不変条件の説明、およびミッションを続ける。

この順序により、登場人物の要望から参加者の分析課題へ自然につなぐ。目次リンクの `#requirement` は維持する。

## 表現とアクセシビリティ

- 会話には「飼い主と受付スタッフの会話」というアクセシブルな名前を与える。
- 各吹き出しは話者名と発話を明示し、DOM上でも飼い主、受付スタッフの順に置く。
- 飼い主の吹き出しは左寄せ、受付スタッフの吹き出しは右寄せとし、発話の往復を視覚的に表す。
- 既存の `--case-lemon`、`--case-mint`、`--case-coral` を使い、モジュールの配色と調和させる。狭い画面では吹き出しをコンテナ幅内に収める。

## 変更対象

- `apps/docs/src/pages/modules/00-read-the-incident.astro`: 会話、参加者への問いかけ、見出しを追加・変更する。
- `apps/docs/src/styles/modules.css`: 会話の吹き出しと参加者向け問いかけのスタイルを追加する。
- `apps/docs/src/test/pages/modules/module-00.test.ts`: 会話の意味的構造・発話内容・DOM順序と、参加者への問いかけを検証する。

## 検証

`pnpm --filter @fp-with-ts/docs test -- src/test/pages/modules/module-00.test.ts` を実行する。テストは、会話が参加者への問いかけより前にあり、飼い主から受付スタッフへ要望が引き継がれることを確認する。
