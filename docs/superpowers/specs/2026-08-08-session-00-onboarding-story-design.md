# Session 00 先人のコードを引き継ぐオンボーディング設計

## 背景

現在の Session 00-A は、動物病院の業務、来院の状態遷移、既存コードを紹介するオンボーディングを含んでいる。一方、セッションタイトルの「導入事故を起こす」と冒頭の導線は事故再現を主役に見せており、参加者がなぜ未知の既存コードを読むのかという物語が伝わりにくい。

参加者を「退職した先人からシステムを引き継いだ新任エンジニア」と位置づける。事故の再現はオンボーディングそのものではなく、業務とコードを知った参加者が最初に担当する仕事として扱う。

## 目的

- Session 00-A のタイトルを「オンボーディング: 退職した先人のコードを引き継ぐ」に変更する。
- セッション冒頭で、参加者が動物病院へ採用された経緯を吹き出し付きの物語として伝える。
- 既存の病院紹介、業務理解、状態遷移、コード観察を「着任初日のオンボーディング」として一続きにする。
- 事故再現、守る不変条件、演習コマンドは変更せず、教材の学習契約を維持する。

## 対象外

- Session 00 の URL、順序、所要時間は変更しない。
- `examples/session-00` の実装、通常テスト、意図的に失敗する演習は変更しない。
- Session 00-B 以降のシナリオやタイトルは変更しない。
- 新しい画像素材や JavaScript による演出は追加しない。

## 体験の流れ

### タイトル

セッションの H1 とセッション一覧で、次のタイトルを使用する。

> オンボーディング: 退職した先人のコードを引き継ぐ

トップページの Session 00 紹介も同じタイトルへ同期する。紹介文では事故を起こすことを参加目的にせず、「先人のコードを引き継ぎ、最初の仕事として既存の事故を観察する」と説明する。

### 冒頭の物語

セッションのヒーロー直後、既存の業務説明より前に、次の3つの吹き出しを順番に表示する。

1. **先人の獣医**

   「この動物病院のシステムは、診療の合間にすべてバイブコーディングで作りました！」

2. **院長**

   「その偉大な獣医さんが退職してしまいました。システムのことを詳しく知る人がいません……」

3. **院長**

   「そこで採用されたエンジニアが、あなたです。まずは病院の仕事と先人のコードを知るところから始めてください」

物語の最後から「着任初日のオンボーディング」へ接続し、既存の動物病院の役割、来院の流れ、登場人物、機能と価値、状態遷移、読むコードを案内する。その後、「最初の仕事」として会計済みの来院が診察中へ戻る事故を提示する。

## 表示設計

- 物語全体を会話としてグループ化し、内容を表す `aria-label` を付ける。
- 各発言は話者名と吹き出し本文を同じまとまりで表す。
- 先人の獣医と院長は配置と背景色を変え、話者の切り替わりを視覚的に示す。色だけに依存せず、話者名を常に表示する。
- 吹き出しのしっぽは CSS で描画し、既存サイトの太い罫線、角丸、レモン色とミント色を踏襲する。
- 狭い画面では吹き出しをコンテンツ幅に収め、文章や話者名が欠けないようにする。
- 既存の Session 00-B の会話表示とは内容と責務を分け、今回の物語に合うクラス名を使用する。

## 変更範囲

- セッションカタログの Session 00-A タイトルと概要。
- Session 00-A ページの目次、冒頭の物語、オンボーディング見出し、事故への接続文。
- トップページの Session 00 紹介タイトル、説明、最初の仕事の文言。
- セッション用スタイルの吹き出し表示。
- セッションカタログ、トップページ、Session 00 ページの構造テスト。

## 受け入れ条件

- Session 00-A の H1 とトップページの紹介に「オンボーディング: 退職した先人のコードを引き継ぐ」が表示される。
- Session 00-A の冒頭に、先人の獣医、院長、院長の順で3つの吹き出しが表示される。
- 吹き出しから、システムがすべてバイブコーディングで作られたこと、先人が退職したこと、参加者が後任エンジニアであることを読み取れる。
- 最初の主要見出しと目次が「着任初日のオンボーディング」になり、既存の業務説明へ続く。
- 会計済みの来院が診察中へ戻る事故、`pnpm exercise:00`、通常テストの説明は維持される。
- 吹き出しは意味のある会話グループとして読み上げられ、各発言の話者がテキストで識別できる。
- `pnpm typecheck`、`pnpm test`、`pnpm build` が成功する。

## 検証方針

Session 00 のページテストで、タイトル、会話グループ、話者、吹き出し数、発言順、オンボーディング見出しを検証する。カタログとトップページのテストでは、変更したタイトルと導線を検証する。既存の Session 00 snapshot と演習コマンドの検証は残し、物語の追加によって学習契約が変わっていないことを確認する。
