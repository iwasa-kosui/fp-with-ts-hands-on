# セッション playground 統合設計

- 日付: 2026-08-30
- 対象: S2〜S6

## 背景

各ページは、設計課題を読む Code Explorer と、後段で編集する Code Explorer を別々に描画しています。前者は読み取り専用、後者は編集用で、作業状態も共有しません。そのため、修正前の失敗を確認する場所と編集場所が離れています。

`CodeExplorer` はガイドを受け取ると読み取り専用になり、ターミナルを表示しません。このモード分岐と、各インスタンス内に閉じた workspace state が重複描画の原因です。

## 方針

- 設計課題は、対象ファイル、該当コード、問題点を示す軽量カードへ変えます。
- 編集可能な Code Explorer は「修正前の失敗を確認する」の直下へ1つだけ置きます。
- WebContainer は利用者がボタンを押すまで起動しません。
- 起動後の最初の操作として、そのセッションの演習コマンドを実行します。
- 同じエディタとターミナルで修正と再実行を続けられるようにします。
- 参加者向け表示では `RED`、`GREEN` を使いません。
- 同じ内容を見出し、説明、期待結果で繰り返しません。
- ローカルとの差分は「ブラウザ内の変更はローカルへ反映されません。」の1文だけで示します。

## 構成

### 軽量ガイド

新しい Astro コンポーネントが `guides` と `projectFiles` を受け取り、各ガイドの対象行だけをサーバー描画します。Monaco、React island、WebContainer は起動しません。既存の source-backed guide 契約は維持します。

### 単一 playground

S2〜S6の編集用 `CodeExplorer` を失敗一覧と修正前コマンドの直後へ移します。後段の「ブラウザで試す」章と2個目の Explorer は削除します。ローカル演習用の `CommandBlock` は残します。

`CodeExplorer` は `initialCommand` を `TerminalPanel` へ渡します。利用者が起動ボタンを押し、シェルが利用可能になった直後に `initialCommand` と改行を1回だけ送ります。起動失敗後の再試行では未実行なら送りますが、シェル再起動時には自動再実行しません。起動後は任意コマンドを入力できます。

編集内容、ファイル追加、ターミナルからの変更は既存の workspace state とファイル監視で同じ Explorer に反映します。ページ内の共有 store は追加しません。

## エラー時の動作

WebContainer 非対応時は起動を拒否し、既存の案内を表示します。エディタとローカル手順は利用できます。起動中断、失敗時のリソース解放、workspace 外への path 逸脱拒否は既存の境界を維持します。

## テスト

- `session-pages.test.ts` から Explorer の個数、固定文言、source 上の配置を検査する assertion を削除します。
- Playwright で S2〜S6の失敗確認セクション内に playground があることを確認します。
- Playwright でモバイルとデスクトップの横スクロールがないことを確認します。
- S2で、初回コマンドの失敗、エディタでの修正、同じコマンドの成功までを1つのブラウザ状態で確認します。
- 単体テストは、ブラウザテストで再現しにくい起動中断、リソース解放、path 逸脱拒否に絞ります。
- `pnpm --filter @fp-with-ts/docs test`、`typecheck`、`build` と対象 Playwright テストを実行します。

## 対象外

- ブラウザ実行を必須経路にする変更
- WebContainer の事前起動
- ブラウザ編集内容の永続化やローカル同期
- セッションの学習目標、演習コード、解答コードの変更

## 完了条件

- S2〜S6に独立した「ブラウザで試す」章がありません。
- 各ページの失敗確認から同じ workspace を編集・実行できます。
- 1ページに全 workspace の Code Explorer を2個描画しません。
- 修正前の失敗、編集、修正後の成功を同じブラウザ状態で確認できます。
- WebContainer 非対応時もローカル手順で継続できます。
- docs のテスト、型検査、ビルド、対象 Playwright テストが成功します。
