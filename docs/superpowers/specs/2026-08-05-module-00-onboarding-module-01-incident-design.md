# Module 00 オンボーディング化と Module 01 事故調査の設計

## 目的

Module 00 を、参加者が WAN NYAN OS、題材の業務、ワークショップの進め方を理解するためのオンボーディングに限定する。会計済みの来院が診察中へ戻るシステム障害は Module 01 へ移し、参加者が事故の意味を理解してから再現・観察できる構造にする。

この変更によって、最初の二つのモジュールの役割を次のように分離する。

- Module 00: どの業務を支えるシステムで、参加者は何を学ぶのかを知る。
- Module 01: 実際に起きた事故を理解し、テストで再現して、次の設計判断へつなげる。

## 背景

現行の Module 00 は、オンボーディング章の後に事故、テスト、ファイル、振り返りを同じ階層で並べている。そのため、詳細な事故報告より先にテストを実行する構成になり、初見の参加者には操作の目的が伝わりにくい。

PRD は、演習を「事故または要求を知る → 失敗を再現する → 不変条件を言語化する → 手段を選ぶ」という順に進めるよう定めている。一方で、Module 00 をオンボーディングとする方針では、Module 00 に演習用の事故・テスト契約を持たせるべきではない。PRD とコンテンツ契約を、この責務分離に合わせて更新する。

## スコープ

### 含めること

- Module 00 をオンボーディング専用ページへ変更する。
- 会計済みの来院を診察中へ戻す事故を Module 01 へ移す。
- 現行 Module 01 のキャンセル理由・再診希望日の要求整理以降を一つずつ順送りする。
- 表示するモジュール番号、slug、URL、演習コマンド、関連テストを新しい連番へそろえる。
- Module 01 を、事故理解・再現・原因観察・次の要求への接続という親子構造のページにする。
- Module 00 を PRD の演習要件の対象外として明文化し、Module 01 以降へ適用する。
- ランディングページ、前後ナビゲーション、ルーティングを新しい開始地点に合わせる。

### 含めないこと

- Module 02 以降のページ構造を今回すべて再設計すること。
- 各演習が扱うドメインルール、解答例、編集量を変更すること。
- 既に公開済みの URL を維持するためのリダイレクトを追加すること。参加者への配布前であるため、旧 URL は廃止する。
- Module 00 でシステム障害の再現、コード閲覧、コード編集を行うこと。

## 参加者体験

### Module 00: 開発に参加する前に

Module 00 は親見出しと子区画を持つ一つのオンボーディング章として表示する。システム障害、`paid`、テストコマンド、編集対象、技法名は表示しない。

1. **このシステムが支える業務**
   - 予約から会計までを扱う動物病院向けシステムであることを説明する。
2. **1 回の来院の流れと登場人物**
   - 予約、受付、診察と記録、会計と完了を、関係する人の役割とともに示す。
3. **このハンズオンで進めること**
   - 既存コードから業務上の問題を発見し、小さく改善して効果を確かめる学習ループを示す。
   - 次の Module 01 では、会計済みの来院記録に起きた事故を調査する、と予告する。

最後には Module 01 への一つの明確なリンクを置く。Module 00 の完了は、参加者が次のモジュールで扱う題材と進め方を説明できることとする。

### Module 01: 導入事故を調査する

Module 01 は、目次に次の親子構造を表示する。すべての子区画は、親区画の目的に対して必要な情報だけを含める。

```text
1. 事故を理解する
   - ミケからの再診依頼
   - 何が壊れるか
   - 今日守る不変条件

2. 自分の環境で確かめる
   - 通常のテストを確認する
   - 事故を再現する
   - 期待する失敗を読む

3. 原因を観察する
   - 最初に読むファイル
   - updateStatus で確認すること
   - 今回は修正しない理由

4. 次の要求へ進む
   - 次に扱うキャンセル理由と再診希望日の要求
   - 振り返り
```

「ミケの再診依頼」と、会計済みの記録を診察中へ戻すと確定済みの診療内容・処方・請求金額を壊すという影響は、テスト実行より前に置く。不変条件は「会計済みの来院は終端状態であり、診察中へ戻さない」と参加者向けの日本語で示し、コード上の `paid` と `in-examination` の対応は事故を理解した後に補助情報として示す。

通常テストの成功は環境確認、演習テストの失敗は事故の再現である。修正を行わない Module 01 では `Red` / `Green` というラベルを使わず、目的を見出しにする。`Green: 効果を確認する` を表示しない。

## コンテンツと表示の設計

`ModuleContent` を、オンボーディングと演習の判別共用体に分ける。

- `OnboardingModuleContent` は、共通の識別情報、オンボーディング章、次のモジュールへの行動を持つ。事故、テスト、編集対象、技法、復帰手順の必須フィールドを持たない。
- `ExerciseModuleContent` は、現在の PRD 契約に加えて、参加者向けの学習章を持てる。既存の演習モジュールは現行の平坦な表示を維持し、Module 01 だけが今回定義する構造化章を使う。

ページレンダラーは `kind` で分岐する。

- オンボーディングページは、ヒーロー、オンボーディング章、Module 01 への導線、前後ナビゲーションを描画する。
- 構造化した演習ページは、ヒーローの後に親 `section` と子 `section` を描画する。既存の目次収集ロジックにより、親子関係がモバイルを含む目次にも反映される。
- 既存の演習ページは、構造化章を持たない限り現在の共通レンダリングを維持する。

Module 01 のデータは、汎用的な `trigger`、`red`、`filesToRead` を画面上で分断して並べず、上記の各学習章が参加者に必要な順番で参照する。これにより、データの都合ではなく、参加者の判断順序で情報を表示する。

## PRD と検証契約

PRD の対象を次のように明記する。

- Module 00 は、演習前のオンボーディングである。
- Module 01 から Module 07 までの各演習は、業務上の事故、要求、またはレビュー要求から始める。
- 演習モジュールにだけ、PRD-02 から PRD-08、PRD-12 のテスト・不変条件・技法・復帰手順の契約を適用する。

`assertModuleMeetsPrd` は演習モジュールだけを受け取る、または判別共用体を受け取ってオンボーディングを明示的に除外する。テストでは、Module 00 が演習契約を持たないことと、Module 01 から Module 07 の全モジュールが契約を満たすことを別々に検証する。

## ルーティングとランディングページ

- Module 00 の正規 URL は `/modules/00-onboarding/` とする。
- Module 01 の正規 URL は `/modules/01-break-the-app/` とする。以降も新しい番号と slug を使う。
- 旧 `/modules/00-break-the-app/` と `/modules/00-read-the-incident/` は解決しない。
- トップページの開始導線は Module 00 を指し、「最初の仕事」として事故を再現する文言は Module 00 の説明から外す。Module 00 の次の導線で Module 01 の事故調査へ進ませる。
- 問題一覧の番号はモジュール番号と混同しない表現へ改める。

## 受け入れ条件

- Module 00 のページと目次に、事故、守る不変条件、テストコマンド、編集対象、技法、`Red` / `Green` が表示されない。
- Module 00 は、業務の文脈、来院の流れ、ハンズオンの進め方、Module 01 への導線を表示する。
- Module 01 の目次には「事故を理解する」「自分の環境で確かめる」「原因を観察する」「次の要求へ進む」の親見出しと子見出しが表示される。
- Module 01 では、詳細な事故シナリオと業務影響が演習テストの実行より先に表示される。
- Module 01 は、コード修正がないことと、今回の到達点が原因の観察であることを明示する。
- Module 02 から Module 07 は、内容の順序を保ったまま新しい連番、URL、演習コマンドで到達できる。
- Module 01 から Module 07 は、更新後の PRD 契約を満たす。
- docs の unit test、typecheck、build が成功する。

## テスト方針

実装では次の順で失敗テストを追加する。

1. Module 00 のデータがオンボーディング専用の契約を満たし、演習用フィールドを要求されないこと。
2. Module 00 のページに演習用の共通見出しがなく、Module 01 へのリンクがあること。
3. Module 01 の目次と DOM が、四つの学習章とその子区画を順番どおりに持つこと。
4. Module 01 で事故説明が演習コマンドより前にあり、通常テストと事故再現の目的が別々に表示されること。
5. モジュールレジストリ、前後ナビゲーション、ルーティング、ランディングページが Module 00 から Module 07 の連番と正規 URL を使うこと。
6. 演習用コマンドとテストが、各モジュールの新しい番号に対応すること。

各テストは実装前に期待どおり失敗することを確認し、最小実装後に対象テスト、docs 全体の test、typecheck、build を実行する。
