# トラブルシューティング

演習は各 Session の「演習」ページのブラウザ内で行います。参加者が詰まったら、画面に出ている文言と使っているブラウザを確かめて、次の順に切り分けます。

## 演習の画面が動かない

### デスクトップ版の Chrome または Edge か

演習の実行環境は、デスクトップ版の Chrome または Edge で動きます。ほかのブラウザを使っている場合は、Chrome または Edge の現行版で同じページを開き直します。

実行環境を起動できないときは、画面に「ChromeまたはEdgeで開き、サイトの分離ヘッダーを確認してください。」と出ます。

### `crossOriginIsolated` が false ではないか

実行環境は、ページの `crossOriginIsolated` が `true` でないと起動しません。ブラウザが Chrome または Edge なのに上の文言が出るときは、ページの `crossOriginIsolated` が `false` で、サイトの分離ヘッダーが効いていないことを疑います。この場合の直し方は教材に書かれていないので、進行役が画面の文言と開いているURLを控えます。

### 「IndexedDB の接続がほかのタブにふさがれています」が出る

作業内容はブラウザの IndexedDB に保存されます。このエラーは、ほかのタブが同じ保存先の接続をふさいでいることを示します。この文言への直し方は教材に書かれていないので、次の対処は未確認です。教材サイトを開いているほかのタブを閉じて、演習のページを再読み込みします。

### 「検出を確かめる」が終わらない、またはタブが前面にない

「検出を確かめる」の実行中に、別のタブやウィンドウを前面にすると、隠れたタブでは実行環境の処理がほぼ止まります。その間に時間切れになることがあります。この時間切れは、参加者の規則やテストの誤りではありません。

画面は次のように出ます。

- 「このタブに戻ると、検出を確かめ直します。」と出たら、参加者に演習のタブを前面に戻してもらい、そのまま待ちます。
- 「タブが隠れていた間に時間切れになったため、確かめ直しています。」と出たら、タブを前面に置いたまま待ちます。

タブが前面にある状態で、「検出を確かめる処理が時間内に終わりませんでした。eslint.config.mjs の規則やテストに、終わらない繰り返しがないか見直します。」と出た場合は、参加者が足した規則やテストに、終わらない繰り返しがないかを見ます。

「結果を読み出せませんでした。もう一度「検出を確かめる」を押してください。」と出たら、もう一度「検出を確かめる」を押します。

### 準備が時間内に終わらない

実行環境の起動や依存パッケージのインストールが時間内に終わらないと、画面に「実行環境の起動が時間内に終わりませんでした。」「依存パッケージのインストールが時間内に終わりませんでした。」「準備が時間内に終わりませんでした。」のどれかが出ます。ターミナル欄が閉じていたら、「ターミナルを開く」を押します。欄が開くと「ターミナルを再試行」のボタンが出ます。画面の案内に従い、ネットワークの接続を確かめて「ターミナルを再試行」を押します。再試行しても同じ文言が出る場合は、原因を会場のネットワークと決めません。上のブラウザ、`crossOriginIsolated`、ほかのタブの項目も確かめます。

### 解答の例を見る

詰まった参加者は、ページの「解答の例を見る」を開きます。

実行環境が起動しないときは、解答の例を読んで次へ進み、相互レビューは隣の人の画面で行います。

## 表の言葉の見方

「検出を確かめる」を押すと、結果の表が出ます。表の言葉は次の意味です。表の下の「表の言葉」を開くと、画面に説明が出る言葉は「誤検知」「対象外」「未検出」「なし」の4語です。

### 結果の列

- 検出: 悪い変更を、型、Linter、テストのどれかが検出しました。その悪い変更で「対象外」と出ていない列の仕組みが検出したときだけ、この結果になります。「対象外」の列が検出しても、行は「すり抜け」のままです。
- すり抜け: 悪い変更を、どの仕組みも検出しませんでした。行を開くとヒントが出ます。
- 未変更: 相互レビューで作る悪い変更を、まだ書き換えていません。最初は正しいコードと同じ内容なので、書き換えるまでこの表示です。
- 誤検知あり: 正しいコードを、悪い変更として検出しました。規則やテストが厳しすぎると起きます。
- 誤検知なし: 正しいコードを、どの仕組みも検出しませんでした。これが良い状態です。
- 未確認: 「検出を確かめる」をまだ押していないため、結果がありません。

必須の悪い変更がすべて「検出」で、正しいコードがすべて「誤検知なし」で、表の下に「問題」が出ていないときに合格です。

### 型、Linter、テストの列

- 検出 N件: その列の仕組みが、N件を検出しました。
- 未検出: 悪い変更の行で、その列の仕組みがまだ検出していません。
- なし: 正しいコードの行で、その列に誤検知がありません。
- 対象外: その悪い変更では、その列の仕組みを数えません。たとえば S6 の型の列は「対象外」です。2回の保存はテストで検出します。
- エラー: その列の確認が失敗したか、テストを読み込めませんでした。参加者が足した規則やテストの書き方に誤りがないかを見ます。

### 「検出」にならないとき

足した仕組みが悪い変更を検出していない場合は、「すり抜け」のままです。行を開いてヒントを読み、足した規則やテストの範囲が狭すぎないかを参加者と確かめます。表に「エラー」が出ている場合は、先にエラーを解消します。原因を会場のネットワークと決めません。

## `pnpm: command not found`

手元で教材サイトやデモ画面を動かす人向けの節です。Node.js 20以上を確認してから、pnpm 9.12.0を導入します。

```bash
npm install --global pnpm@9.12.0
pnpm --version
```

グローバルパッケージをインストールできない端末では、端末の管理者にpnpm 9.12.0の導入を依頼してください。Node.js 25以降にはCorepackが同梱されないため、Corepackが使えることを前提にしません。

## Node.js version too old

手元で教材サイトやデモ画面を動かす人向けの節です。`node --version` が `v20` 未満の場合は、Node.js 20以上へ更新します。切り替え後にターミナルを開き直して確認してください。

```bash
node --version
pnpm --version
```

## install fails

手元で教材サイトやデモ画面を動かす人向けの節です。リポジトリのルートとネットワーク接続を確認します。依存関係は会場へ来る前に取得してください。

```bash
pwd
pnpm install --frozen-lockfile
```

権限、証明書、社内プロキシのエラーが含まれる場合は、端末の管理者へ相談してください。

## 外部ディスプレイへ正しく映らない

会場の外部ディスプレイ、HDMI、USB-C変換アダプタ、電源は未確認です。使える場合だけ接続し、画面はミラーリングにします。拡張表示のまま別画面へウィンドウが残っていないか確認してください。

ブラウザの表示を一時的に拡大し、対象の1ファイル・20行以内だけを表示します。利用できない場合は参加者のラップトップを島の中央へ向けます。口頭説明だけで相互レビューを済ませません。

## 開発サーバーのポートが使用中

手元で `pnpm dev` を動かす人向けの節です。起動中のサーバーが分かる場合はそのターミナルで `Ctrl+C` を押します。分からない場合は別ポートを指定します。

```bash
pnpm dev --port 5174
```
## 相互レビューが時間内に終わらない

相互レビュー自体は落としません。[班内相互レビュー進行カード](./peer-review-card.md)の持ち時間は、時間割の相互レビュー、guard、review を足した時間です。S1 と S2 は3分、S3 と S6 は5分、S4 は6分です。

時間が足りないときは、カードの短い版にします。S3 と S6 は3分版、S4 は4分版です。S1 と S2 はもともと3分なので、通常の進め方のままです。どの版でも、シートへ書く最後の1分は残します。

次の回では、まだ選んでいない人を優先します。5回で全員を最低1回選べるように、カード裏面のピックアップ記録を使います。
