## Checkpoint

### 0:18 不変条件を確認する

次の点を確認してから `02-state-vocabulary` に進みます。

- 会計済みの来院を診察中へ戻さない、という業務ルールを一文で説明できる
- Session 00 では legacy を直さず、事故を再現できることが次の変更の開始条件だと説明できる
- Session 01 の要求と次の snapshot の状態語彙が対応していると確認できる

### 1:07 境界へ進む

参加者が `AwaitingPayment`、`Paid`、`Canceled` を区別し、どの状態から何を行えるか説明できたら、Session 06 の外部入力 payload を表示します。

### 1:40 失敗と event へ進む

次の点を確認してから `09-typed-failures` に進みます。

- 外部入力は Zod、ID・時刻・金額は branded value、PII 出力は `Sensitive` と、別々の責務で守ると説明できている
- `Sensitive` は入力検証を代替せず、redaction は PII の閲覧権限を決めないと説明できている

### 2:22 原子性へ進む

次の点を確認してから `12-atomicity-and-conflicts` に進みます。

- 失敗理由を `throw` ではなく呼び出し元が扱える `Result` の値で返すと説明できている
- 成功時だけ event を作り、event は event sourcing や通知の代わりではなく業務上の事実だと説明できている
- `ResultAsync` use case が失敗時に store を呼ばないことを exercise で確認できている

## 進行上の注意

- 参加者の環境トラブルは、まず [トラブルシューティング](./troubleshooting.md) の該当項目で切り分けます。
- 赤いテストを先に直してしまわず、どの不変条件が破られたかを全員で確認します。
