# ファシリテーター向けガイド

## イベント概要

- 開催日時: 2026年8月30日 15:00-18:00（180分）
- 体制: 5人1班、各班にTA 1名
- 対象: TypeScript の基本文法を読み書きできる初級から中級の参加者
- 題材: 動物病院の予約・カルテ管理システム
- 主線: 事前にセットアップしたローカル clone
- 退避先: セッションページのステップ解答と WebContainer Playground

コーディングエージェントは推奨ですが必須ではありません。参加者が担うのは、事故から不変条件を言語化し、依頼文または実装メモへ変換し、型とテストで個人検証したうえで班内相互レビューを行うことです。

## テストと演習コマンドの契約

- `pnpm test`、`pnpm typecheck`、`pnpm build` は通常の健全性確認で、成功を期待します。
- S1〜S4 の開始スナップショットでは、`pnpm exercise:01`〜`pnpm exercise:04` が業務語彙を持つ `AssertionError` で意図的に失敗します。module-not-found、import error、設定エラーは意図した RED ではありません。
- 参加者が対象モジュールを直した後は、同じ exercise コマンドの成功を期待します。
- S0 と到達点 `examples/session-05` に exercise コマンドはありません。
- S3 は同期 `Result` と `andThen`、S4 は副作用・イベント、`ResultAsync`、`andThrough`、1回の `store(event)` を扱います。

参加者ステップは S1=4件、S2=2件、S3=3件、S4=4件です。開始時の RED 数と同じではない出力や予期しない例外を見たら、先に環境または差分範囲を切り分けます。

## 講師の共通台本

S1〜S4 は次の順序を崩しません。

1. 要求と事故を読み、「何が壊れたか」を業務の言葉で確認する。
2. exercise コマンドを実行し、意図した assertion RED を見る。
3. 参加者が「〜が〜できない」の形で不変条件を1文にする。
4. その1文を依頼文へ入れる。エージェントを使わない参加者は実装メモとして使う。
5. 対象モジュールだけを変更し、同じコマンド、型、`git diff --stat` で個人検証する。
6. TA が選んだ1〜2名の差分を班で相互レビューし、全員がレビュー観点シートへ1行書く。

S0 では修正と exercise 実行を行いません。Final は講師が `examples/final/src/useCase/startExaminationUseCase.ts` を入口に5分で案内するだけです。参加者へ `examples/final` のセットアップ、編集、Playground 操作を求めません。

## Checkpoint

### 0:25 — S0 を終えて S1 へ進む

- 2件の事故（二重請求、PII流出）と legacy の該当行を対応づけられるか確認する。
- 5つの弱点を先回りして直さず、S1で最初に状態の逆行を扱うことを共有する。
- S1の前に、[相互レビュー進行カード](./peer-review-card.md)の約束事5点を読み上げる。4回で全員を最低1回選ぶ計画をTAが記録欄へ立てる。

### 0:55 — S1 を終えて S2 へ進む

- 5状態と許可された遷移、キャンセル理由、`assertNever` の役割を確認する。
- 4ステップを完走できない参加者は、ページのステップ解答を開いて同じ型を読める状態にする。
- 相互レビュー7分は落とさない。時間超過時は2人目の比較枠2分を落とし、1名の5分版へ切り替える。

### 1:25 — S2 を終えて休憩へ入る

- 不正JSONが `err` になり、連絡先が JSON と inspect の両方で伏せられることを確認する。
- 参加者ステップは catalog の2件である。時間が足りなければ、末尾のステップから講師デモへ切り替える。固定の「Step 3/4」が存在する前提で進行しない。
- 相互レビュー7分は残し、必要な場合だけ2人目の比較枠を落とす。休憩10分を削らない。

### 2:10 — S3 を終えて S4 へ進む

- `AppointmentNotFound` と `InvalidAppointmentState` が例外文言ではなく同期 `Result` の値として返ることを確認する。
- S3の3ステップが終わらない場合は `ensure*` の解答と `andThen` pipeline を順に開き、失敗後に遷移しない理由を読ませる。
- 後半の残り時間を確認し、S4が押す見込みなら S4のステップ3（`ResultAsync` と `andThrough`）を講師デモにする。S4の相互レビューは残し、次に2人目枠、最後にFinalの説明量を調整する。

## 班とTAの運用

オープニングでエージェント有無を申告してもらい、可能な範囲で保持者と非保持者を同じ班にします。TA は保持者0名の班を把握します。

委譲時間の巡回には2つの目的があります。

1. 赤の数、型エラー、モジュール外差分から詰まりを発見し、エージェントを使わない参加者を優先して支援する。
2. [相互レビュー進行カード](./peer-review-card.md)の選定基準に沿って、学びの出る1〜2名の差分を選ぶ。

相互レビューの末尾1分では、自分の差分が選ばれなかった参加者も [レビュー観点シート](./review-sheet.md) の「型で守れなかった残り」を書きます。2名を選ぶ回を3回以上確保し、4回を通して班の全員が最低1回は選ばれるよう、カード裏面の記録欄で調整します。

## エージェントを使わない参加者の退避

- ページの「ステップごとの解答」を1件ずつ開き、次スナップショットの実ソースを写して理由を読む。
- `配布コードを読む` の Code Explorer は、実ファイルの注目行を読むためのガイドとして使う。
- `型で閉じる` の Playground は WebContainer 上で編集とコマンド実行ができる説明用・退避用環境として使う。主線にはせず、会場ネットワークに依存させない。
- Playground が起動しない場合はローカル clone へ戻る。新しいAPIキーや特定のエージェント製品は必要ない。
- 相互レビューではモジュール全体ではなく、全員が到達している1ステップ・1宣言を対象にする。解答を写した差分なら「なぜ解答はこの形か」「別の形だと何が壊れるか」と問う。

Code Explorer の専用URLはありません。各セッションの `配布コードを読む` と `型で閉じる` に埋め込まれた実体を使います。

## 事前リハーサル手順

自動検証の実測結果はP4のリハーサル記録へ残します。このガイドでは実行順と期待だけを定めます。

1. 依存関係を事前に取得し、`pnpm typecheck`、`pnpm test`、`pnpm build` が成功することを確認する。
2. 4つの exercise コマンドを個別に実行し、開始スナップショットとして non-zero の assertion RED になり、参加者ステップが S1=4、S2=2、S3=3、S4=4 に対応することを確認する。
3. `pnpm --filter @fp-with-ts/clinic-session-05 test` が S1〜S4 の全回帰を含めて成功することを確認する。
4. 5人相当の差分で7分版を通し、問い1で沈黙しないか、2人目の比較まで収まるかを計測する。成功済みとは記録せず、実測結果をP4へ残す。
5. エージェントを使わない条件で、ステップ解答を開いて委譲時間内に進めるかを1本計測する。

スマホ表示を確認するときは開発サーバーを `0.0.0.0` で待ち受けます。現行の `pnpm dev` はこの設定を持ちます。表示された実ポートに対して `mobile-preview-url <port>` を実行し、返されたURLを使います。明示的な依頼がない限り公開トンネルは使いません。
