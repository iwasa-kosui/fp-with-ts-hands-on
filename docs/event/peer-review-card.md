# 班内相互レビュー進行カード

印刷想定: A5・両面・各班のTAに1部。表面を進行、裏面を記録と例外対応に使います。

## 表面 — 選ぶ・進める・問う

### 現在snapshotの差分を映す

| セッション | 差分確認 |
| --- | --- |
| S1 | `git diff --stat -- examples/session-02` |
| S2 | `git diff --stat -- examples/session-02`（S1 の変更が残るので、今回の変更が `statusLabel.ts` だけであることも確かめる） |
| S3 | `git diff --stat -- examples/session-04`（補助演習は `git diff --stat -- examples/session-03`） |
| S4 | `git diff --stat -- examples/session-05` |
| S6 | `git diff --stat -- examples/session-06` |

最初に `git status --short` で全体の想定外pathを探し、比較する差分量は表の現在snapshot限定コマンドで判定します。前のセッションの未commit差分は比較へ混ぜません。

### 差分の選定基準（上から優先）

完成度では選びません。同じ課題に対する設計判断の違いが見える差分を選びます。

1. 同じ問題を、型で防いだ差分と実行時の `if` で防いだ差分の対
2. `as` によるキャストが残っている差分
3. 現在snapshot限定の差分と `git status --short` で、今回の演習モジュール外にも変更が見える差分
4. Agentへの依頼文が明確に異なる2名の差分
5. テストは成功しているが、設計判断を1件落としている差分

委譲時間中に5人の画面を1周し、対象者へレビュー開始前に伝えます。TAは、同じ課題に対して設計判断が異なる差分を選びます。完成度や技能による選出ではありません。5回で全員が最低1回は選ばれるよう、S2 は1名、ほかの回は原則2名を選び、裏面へ記録します。

### セッション別の問い

#### S1: 状態と遷移

1. `startExamination` は `CheckedIn` だけを受け取り、会計済み・キャンセル済みを型で拒否しますか。
2. `recordPayment` は `AwaitingPayment` だけを受け取り、診察結果の記録前には会計できない型ですか。

#### S2: 状態の分岐漏れ

1. 状態を追加したとき、`assertNever` によって未対応の分岐がコンパイルエラーになりますか。
2. `toStatusLabel` は `Readonly<{ kind: string }>` ではなく、`Appointment` を受け取っていますか。
3. `default` 分岐は固定の表示名を返さず、`assertNever` に `appointment` を渡していますか。

#### S3: 診察開始の外部入力

1. 不正な予約IDまたは獣医師IDを含む入力は、`StartExaminationInput` になりませんか。
2. `parse` は外部入力を `unknown` として受け取っていますか。
3. 検証に成功した場合だけ、`AppointmentId` と `VeterinarianId` をユースケースへ渡せますか。

#### S4: 業務エラー

1. 予約なしと状態不正は、異なる `kind` を持つ `Err` になっていますか。
2. `andThen` は、失敗後の状態遷移と保存を実行しない構造になっていますか。
3. Web側は業務エラーを `kind` で網羅し、未対応の種類を型エラーにできますか。

#### S6: 副作用と整合性

1. 時刻とイベント ID は実行ごとに一度だけ生成され、同じ `EventContext` に入りますか。
2. 状態と監査記録は、1つのイベントとして同じ `store` に渡されますか。
3. 業務上の競合だけを `Result` で返し、保存障害は reject のまま伝播しますか。

### 進行上の約束事

1. 人ではなく差分を見ます。「この差分は」で話し始め、優劣をつけません。
2. 本人はAgentへの依頼文だけを読み上げ、弁明しません。
3. TAは、同じ課題に対して設計判断が異なる差分を選びます。完成度や技能による選出ではありません。
4. 5回で班員全員を少なくとも1回選びます。

### 次のセッションへの引き継ぎ

レビュー末尾の記録後、表のpathだけを次のsnapshotへ切り替えます。前のセッションの未commit差分を消すための reset、stash、commit は求めません。想定外pathを見つけても自動で戻さず、本人と残す作業を確認します。

### 例外1 — エージェント非保持者を選ぶ

S3またはS4で1回を目安にし、班の全員が到達している1ステップ分に絞ります。ステップ解答を写した差分なら、「なぜ解答はこの形か」「別の形だと何が壊れるか」と読み替えます。

### 例外2 — 保持者が0名の班

5回とも非保持者から選び、対象を常に1ステップへ絞ります。型で守った差分と `if` で守った差分の対を最優先にします。

### 例外3 — 外部ディスプレイがない

会場の映像設備は未確認です。使えなければ、選ばれた参加者のラップトップを島の中央へ向け、フォントを一時的に拡大し、対象を1ファイル・20行以内に絞ります。口頭だけでは型と `if` の境界を確認できないため、画面は省きません。

### 例外4 — 時間超過

相互レビュー自体は落としません。2人目の比較を落とし、S1は1名の3分版、S3は1名の5分版、S4・S6は1名の6分版にします。S2 はもともと1名です。シート記入の最後1分は残します。
