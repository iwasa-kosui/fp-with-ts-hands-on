# 班内相互レビュー進行カード

印刷想定: A5・両面・各班のTAに1部。表面を進行、裏面を記録と例外対応に使います。

## 表面 — 選ぶ・進める・問う

### 相互レビューの対象を確認する

| セッション | 確認 |
| --- | --- |
| S1 | 確認は要りません（ブラウザの演習） |
| S2 | 確認は要りません（ブラウザの演習） |
| S3 | 確認は要りません（ブラウザの演習） |
| S4 | 確認は要りません（ブラウザの演習） |
| S5 | 相互レビューはありません（ブラウザの演習が6分あります） |
| S6 | 確認は要りません（ブラウザの演習） |
| Final | 相互レビューはありません（演習もありません） |

TAは、各自のブラウザの演習の画面を見て、相互レビューの対象を選びます。S5 と Final に相互レビューはありません。

### 相互レビューの対象の選定基準（上から優先）

完成度では選びません。同じ課題に対する設計判断の違いが見える仕組みを選びます。

1. 同じ問題を型で検出している仕組みと、テストで検出している仕組み
2. 「検出を検証する」で、相互レビューで作る誤った変更が「すり抜け」になった仕組み
3. ルールやテストの範囲を狭めて、誤検知を消した仕組み
4. どの誤った変更をどの仕組みで検出するかを、追加する前に決めた判断が明確な仕組み
5. 必須の誤った変更は検出できているが、設計判断を1件落としている仕組み

TAは、演習の時間中に5人の画面を1周し、対象者へレビュー開始前に伝えます。TAは、同じ課題に対して設計判断が異なる仕組みを選びます。完成度や技能による選出ではありません。5回で全員が1回ずつ選ばれるよう、各回で1名を選び、裏面へ記録します。

### セッションごとの持ち時間

| セッション | 相互レビュー | 原則 |
| --- | ---: | --- |
| S1 | 3分 | 1名 |
| S2 | 3分 | 1名 |
| S3 | 5分 | 1名 |
| S4 | 6分 | 1名 |
| S6 | 5分 | 1名 |

### 3分版（S1・S2）

| 経過 | 進行 |
| --- | --- |
| 0:00-0:30 | 隣の人のブラウザの前に移る |
| 0:30-1:00 | 相手の仕組みを読む |
| 1:00-2:00 | S1 は表の「相互レビューで作る誤った変更」の行を選ぶ。S2 は左の一覧から同じ名前の項目を開く。どちらも、検出されない誤った変更を1行で作って「検出を検証する」を押す |
| 2:00-3:00 | guard ページへ進む。話すのはカードの「セッション別の問い」から1つ（S2 は default の問い）。全員がシートへ1行書き、1名が読んで締める。guard ページの問いは進行役が読み上げ、参加者が担当業務で検討する |

### 5分版（S3・S6）

| 経過 | 進行 |
| --- | --- |
| 0:00-0:30 | 隣の人のブラウザの前に移る |
| 0:30-1:00 | 相手の仕組みを読む |
| 1:00-2:00 | 左の一覧から「相互レビューで作る誤った変更」を開き、検出されない誤った変更に書き換えて「検出を検証する」を押す |
| 2:00-3:00 | ページの3つの問いを話す（ここまでが peer-review ページ） |
| 3:00-4:00 | guard ページを読む。S3 は、3つの仕組みを比べて、担当業務で使う仕組みを選ぶ。S6 は、「1回の保存」と「原子性」を、それぞれどの仕組みで守るかを話す |
| 4:00-5:00 | review ページで、全員がシートへ1行書き、1名が読んで締める |

### 6分版（S4）

| 経過 | 進行 |
| --- | --- |
| 0:00-0:30 | 隣の人のブラウザの前に移る |
| 0:30-1:30 | 相手の仕組みを読む |
| 1:30-3:00 | 誤った変更を作って検証する |
| 3:00-4:00 | ページの3つの問いを話す（ここまでが peer-review ページ） |
| 4:00-5:00 | 担当業務での防止策（guard） |
| 5:00-6:00 | 担当業務への適用（review）。話した内容をシートへ1行書く |

### セッション別の問い

#### S1: 状態と遷移

1. 何を変えたか。
2. 何を追加すれば検出できるか。
3. 誤検知は発生しないか。

#### S2: 状態の分岐漏れ

1. default を残したいのはどんなときか。残すなら何で漏れを検出するか。

#### S3: 診察開始の外部入力

1. 検出されなかった変更は何を変えたのか。
2. その変更を検出するには何を追加すればよいか。
3. 追加した仕組みで誤検知は発生しないか。

#### S4: 業務の失敗

1. 検出されなかった変更は何を変えたのか。
2. その変更を検出するには何を追加すればよいか。
3. 追加した仕組みで誤検知は発生しないか。

#### S6: 副作用と整合性

1. 検出されなかった変更は何を変えたのか。
2. その変更を検出するには何を追加すればよいか。
3. 追加した仕組みで誤検知は発生しないか。

### 進行上の約束事

1. 人ではなく仕組みに注目します。「この仕組みは」で話し始め、優劣をつけません。
2. 本人は自分の仕組みの狙いを1文だけ話し、弁明しません。
3. TAは、同じ課題に対して設計判断が異なる仕組みを選びます。完成度や技能による選出ではありません。
4. 5回で班員全員を少なくとも1回選びます。

### 次のセッションへの引き継ぎ

レビュー末尾の記録後、次のセッションへ進みます。手元の reset、stash、commit は要りません。次のセッションの演習は、そのセッションのページのブラウザの演習で始まります。

### 例外1 — 外部ディスプレイがない

会場の映像設備は未確認です。使えなければ、選ばれた参加者のラップトップを島の中央へ向け、フォントを一時的に拡大し、対象を1ファイル・20行以内に絞ります。口頭だけでは相手のルールとテストが何を見ているかを確認できないため、画面は省きません。

### 例外2 — 時間超過

相互レビュー自体は落としません。時間が足りないときは、S3 と S6 は3分版、S4 は4分版にします。S1 と S2 はもともと3分なので、通常の工程のままです。シート記入の最後1分は残します。
